### T는 그날의 아이디어에 따라 달라집니다.

| T | 우리가 만드는 것 |
| :--- | :--- |
| **Trash develop** | “이런 것도 되나?” 싶은 엉뚱한 아이디어. 일단 만들어 보면 쓸모를 발견할지도. |
| **Tech develop** | 궁금했던 기술을 직접 붙여 보고, 가능성을 확인하는 작은 실험. |
| **Thinking develop** | MBTI의 T처럼, “왜?”를 묻고 코드로 가설을 검증하는 문제 해결. |

어떤 T로 시작해도, 끝에는 **직접 실행해 볼 수 있는 무언가**를 남깁니다.

### 하루의 아이디어가 하나의 빌드가 되기까지

**01 · 발견** → **02 · 구현** → **03 · 검증** → **04 · 기록**

- **발견** — 작은 불편, 호기심, 엉뚱한 상상에서 오늘의 질문을 고릅니다.
- **구현** — 하루 안에 확인할 수 있도록 범위를 줄이고 핵심 기능을 만듭니다.
- **검증** — 직접 실행해 보며 정말 작동하는지, 어떤 의미가 있는지 확인합니다.
- **기록** — 코드와 실행 방법, 결과와 배움을 남겨 다음 실험으로 이어 갑니다.

### 우리가 생각하는 ‘의미 있는 프로그램’

작은 불편 하나를 덜어 주거나, 기술의 가능성을 확인하거나, 누군가에게 재미를 주는 것.
예상대로 되지 않았어도 **무엇을 배웠는지 남았다면 다음 빌드의 재료**가 됩니다.
